# 视频压制与 HDR 契约

[English](../export.md) | [简体中文](export.md)

工作台压制当前工程的不可变快照，独立 `aegn-exporter` 进程共享 Core 场景求值和 Rendering 绘制。项目仍名为 `AegiNext.ExportWorker`；部署的 apphost／DLL 名称由 `AssemblyName` 决定。界面提供自动／H.264／HEVC、CPU 或 GPU 视频编码、原音轨复制／AAC／无音频、进度和取消，输出 MP4 或 Matroska。

目标必须是新文件；worker 在输出目录的独立临时目录中编码，成功后原子提交，失败和取消清理本次临时文件，不能覆盖已有成片。导出期间继续编辑不会改变正在运行的快照。发布必须包含 worker apphost、DLL、deps／runtimeconfig、托管依赖与同版本原生库，不能只复制桌面可执行文件。

## CPU 与 GPU 编码

默认 CPU 编码使用 `libx264`／`libx265`，保留速度和 CRF 控制。勾选“使用 GPU 硬件视频编码”后使用视频码率，范围 0.1–200 Mbps，默认 8 Mbps。两种模式分别保留参数；隐藏的另一模式输入不阻碍当前模式压制。进度、完成状态与日志显示实际编码器名称。硬件请求完成时还会验证 worker 返回的编码器身份；混用旧 worker、缺少身份或返回软件编码时不会提交成片。

macOS 使用 VideoToolbox，并禁止软件回退。Windows 按可用的 NVIDIA NVENC、Intel QSV、AMD AMF 实际初始化编码器；未安装驱动、虚拟机没有暴露硬件编码能力、SDK 没有对应编码器或初始化失败时，明确报告诊断，不自动退回 CPU。可以取消 GPU 选项后使用软件编码。

该选项加速视频编码；视频解码和字幕线性合成仍沿用现有路径。GPU 支持 SDR H.264 8-bit 与 HEVC 10-bit。HDR 的完整元数据保留目前只在软件 HEVC 路径验收，选择 GPU 压制 HDR 时明确拒绝并提示使用 CPU。

## 色彩链路

视频解码保留原始整数 YUV、PTS、位深、范围、原色、传递函数、矩阵及受支持元数据。原生 `native/export` 将背景转为明确的线性浮点亮度，转换并合成线性 BT.709 / F16 字幕与图形，再按源信号反变换、编码。未覆盖的透明区域保持源代码值，HDR 背景不经过预览 BGRA8。

- SDR 支持 H.264 8-bit 或 HEVC 10-bit。
- PQ／HLG 自动使用 HEVC 10-bit；显式 HDR + H.264 会被拒绝。
- PQ 使用绝对亮度传递，字幕默认参考白 203 nits；HLG 明确采用 1000-nit 显示条件与零黑位处理 OOTF。
- 完整、静态的 HDR10 mastering display 信息保留。MaxCLL／MaxFALL 在合成后写未知 `0/0`，避免沿用未经重新计算的源内容亮度统计。
- Dolby Vision、HDR10+／其它动态 HDR、变化的 mastering 信息或不完整的 mastering 信息不支持，遇到时明确失败。

工程蒙版、模糊与中间分组同样保持 F16，支持正常、正片叠底、滤色、相加、叠加、变暗、变亮和差值。相加等模式可保留超过参考白的值；颜色选择器显示范围的限制不改变工程已有扩展亮度。

## 支持条件与拒绝行为

首版要求明确的色彩字段、整数平面 YUV 8～16-bit、已知受支持的色度位置、方形像素和工程画布等于视频可见尺寸。源逐帧时间戳传给编码器，VFR 不强制转 CFR。旋转／立体／ICC、隔行、损坏帧、动态格式变化及其它当前无法保持的语义会被拒绝；负 PTS 在 NUT 中不能表达时也失败，不暗中归零。

音频复制保持编码包内容；AAC 按选择码率重编码，无音频模式显式去除音轨。保留时间戳不保证任意媒体的起点组合都被所有封装器支持，封装失败会显示具体诊断。

## 已执行验证

原生色彩数值和独立 worker 集成覆盖 SDR、PQ／HLG、VFR、源音轨复制、AAC、取消、不覆盖旧文件及 HDR/H.264 拒绝。PQ 的 1000／4000-nit 高光回读码值为 723／855；203-nit 白字幕以 50% alpha 合成到 1000-nit 背景后回读 675，理论值约 674.52。HLG 对应条件回读 872。

这些验证检查成片像素和元数据，不以“保留 HDR 标签”作为保真证据。本轮 CPU／GPU 与平台结果见 [Checkpoint](checkpoints/export-title-colors.md)；真实 HDR 显示器观感及未具备的物理 GPU 路线须单独验收。
